## 二、阶段与顺序

```text
Phase 3.1  基线收口（审计缺口）
Phase 3.2  自动胶片范围识别优化
           ── tag：v1.2-clean-baseline.1（不移动已推送的 v1.2-clean-baseline）──
Phase 4    PR #10 代 rebase 与集成（含天空高光验收）
Phase 5    反相偏色重新定基线 + 天空过曝诊断/收口
Phase 6    RC：macOS 全面验证 + 全量回归 + 发布
```

**为什么 3.2 排在 PR #10 之前**：胶片范围是反相分析（片基、窗口）的输入。先把输入定住，Phase 4/5 的 A/B 只需要做一次，也不会把"框错了"和"色彩基变了"两种原因混在一起。识别只影响新导入和重新识别的帧，不改已持久化的帧，所以不需要升 `RAW_DECODE_VERSION`。

## 四、自动范围识别：选型决策

现状（`src/film_border.rs`）：分析图点采样降到 320 长边 → Sobel 投影找四条边 → 逐边拟合直线（已能处理小角度倾斜）→ `refine_to_gate` 从片身外沿向内走到片门（已经是"两阶段"）→ 失败时回退全图 `[0,0]-[1,1]`。另外，Phase 2 之后胶片范围**只影响分析、不影响渲染**，所以向内收一点没有画面代价。

| 提案 | 决策 | 理由 |
|---|---|---|
| 1. 分析分辨率 640 + 面积均值降采样 | **采纳** | 现在是逐像素点采样，有混叠，结果随输入尺寸漂移；改动小、确定性强。用 640，不用 800：缩略图本身约 1–1.6k，800 收益有限。 |
| 2. LSD/霍夫 + RANSAC 重写 | **不采纳（v1.2）** | Rust 生态没有成熟的 LSD，等于重写检测器，风险大。现有逐边拟合已经能处理倾斜。若 3.2 评测集显示倾斜或局部误导确实是主要失败类型，再立项到 v1.3。 |
| 3. 画幅比例先验 | **采纳，只作软先验** | 只在候选打分时加权、在不像标准画幅时降置信度，**不硬剔除**。XPan（约 2.7:1）、6×17、半格都是合法画幅，"1:2.8 就剔除"会误杀。Roll 上记录了画幅时，以它为最强先验。 |
| 4. 两阶段 + 安全内缩 | **部分采纳** | 两阶段已有，不重做。新增：只在检测结果上（不在用户手动框上）默认向内收缩 **1.0%**，做成常量。 |
| 5. 卷级空间先验 | **采纳** | 翻拍架固定，整卷位置稳定。用户确认过的帧或前几张高置信结果作为先验，后续帧在 ±5% 窗口内细化。局部检测失败时继承先验，标记为低置信。门控：只有先验帧之间彼此一致才启用（扫描仪条带位置会变）。 |
| 6. 失败回退 + UI 交互 | **采纳** | 失败时回退到居中 80% 的框，比例取 Roll 画幅，否则 3:2；不再回退全图。UI 增加 [3:2][1:1][6:7][自由] 比例锁、整体拖动和单边拖动。 |

**验收依赖评测集**：用户在真实库里手动确认过的胶片范围就是标注真值。指标：
- 角点误差；
- 漏光像素（框内落在真值外的面积）——必须为 0；
- 整卷抖动；
- 640 / 1024 / 1600 三种输入下的结果一致性。
