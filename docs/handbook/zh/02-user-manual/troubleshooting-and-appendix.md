## 影调与色彩异常系统排障树 {#tone-and-color-troubleshooting}

在胶片数字化暗房中，反相异常往往并非软件程序本身的逻辑缺陷，而是由前期光学翻拍、片基采样污染或边界框选失误所致。建立系统化的「表象症状 → 物理根因诊断 → 逐步排除路径」思维模型，能够帮助摄影师在几秒钟内定位问题核心。

> [!NOTE] 真实低反差与算法错误的区别
> 如果拍摄底片本身记录的是清晨大雾、阴雨密云或昏暗室内，画面物理直方图本身就不具备纯白高光或深邃纯黑。NexFilm 的物理管线坚守真实还原，绝不会为了迎合所谓的“通透感”而盲目强行将直方图两端死死顶死。摄影师应当允许真实的低反差存在，在需要艺术强化时再通过“曲线”面板按需调整。

## 文件解码与性能排障 {#decoding-and-performance}

针对数字资产导入与实时渲染中可能遇到的技术瓶颈，处理建议如下：

### 1. 相机 RAW 或哈苏 .fff 文件导入报错或解码失败
- **检查扩展名真实性**：某些第三方软件转存的 RAW 可能会伪造扩展名，确保文件由相机或扫描仪原生生成。
- **Nikon Z8 / Z9 高效率压缩 NEF 限制**：如前所述，内置 LibRaw 暂不支持 `HE` 与 `HE*` 编码。解决途径为在相机机内改用常规无损压缩重新翻拍，或使用官方免费的 Adobe DNG Converter 批量转为标准 DNG。
- **哈苏 Flextight `.fff` 确认**：自 v1.1.0 起已原生支持扫描仪 TIFF 解码管线，无需再行修改设备标识符字符串。若遇报错，检查源文件是否在 FlexColor 中保存为非标准分块格式。

### 2. 超大扫描仪 TIFF（数百兆至数 GB）内存占用与卡顿
- 扫描 8×10 大画幅生成的 16-bit TIFF 往往达到数 GB 级别。NexFilm 采用按行流式切片读取技术，在进入工作台时仅加载 2560 px 有界代理。若系统在导入阶段发生偶发卡顿，请确认系统虚拟内存页面文件（Swap/Pagefile）至少预留了 16 GB 磁盘空余空间。

### 3. 工作台预览与最终全尺寸导出存在微小视觉差异的原因
- **有界代理与全分辨率流式解算的分工**：工作台预览实时运行在长边 `2560 px` 的高质量有界代理图上，而导出则从磁盘拉取原始高分辨率矩阵进行全图计算。
- **锐度与颗粒微观表现**：虽然细节面板的全部锐化与清晰度半径均以长边 2560 px 严格等比换算，但在宏观上保持了完全相同的相对锐度；但在极高倍率放大下，数千万像素原始文件的微观银盐颗粒分布在抗锯齿重采样下会显现出更丰富的细节。正式批量输出前，先导出一张具有代表性的画面进行试片，是暗房操作的标准范式。

### 4. 从 v1.0.2 升级至 v1.1.0 后缩略图变黑或清空
- 在 v1.1.0 中，底层物理密度反相模型进行了重构升级。为防止旧版本中依据错误物理公式渲染的陈旧缩略图误导用户，数据库迁移程序在首次启动时会安全清空旧配方缩略图。用户只需进入胶卷，点击一次 **自动反相** 或 **整卷批处理**，系统即可瞬间按全新物理管线重建所有缩略图。

### 核心数据库与镜像文件职责
- `nexfilm_user.db`：应用的主 SQLite 数据库。存储了全部胶卷元数据、拍摄机身与乳剂字典、画面索引树、历史调色参数栈、输入域色彩科学记录以及长边 2560 px 有界代理缓存。该数据库**不包含完整的原始图片文件副本**，只记录其磁盘物理路径。
- `rolls.json`：用于向后兼容与外部快速索引的镜像文件，在数据库提交时自动同步写入。

### 黄金备份与迁移准则
> [!IMPORTANT] 备份必须遵循“源片 + 数据库”双轨制
> 由于 NexFilm 坚决不复制原始大文件，**仅备份 `nexfilm_user.db` 无法在原片丢失后恢复图像**；反之，仅备份原图而丢失了数据库，则在重新导入后必须重新手动标定与调色。
> 正确的备份策略为：
> 1. 定期备份存储原始 RAW/TIFF 的物理磁盘目录；
> 2. 同步备份上述平台对应的数据目录（特别是 `nexfilm_user.db`）。
> 在更换电脑迁移数据时，只需将原图与数据目录拷贝至新设备相同路径下即可无缝继续工作。

## 已知限制诚实披露清单 {#known-limitations}

作为秉承科学态度研发的开源软件，NexFilm 诚实披露当前版本存在的已知技术边界：

1. **未购买商业机构代码签名证书**：当前 Windows 安装包与 macOS `.dmg` 磁盘镜像均由开源社区通过自动化 CI 构建生成，未向商业认证机构付费购买昂贵的企业级代码签名证书，macOS 安装包尚未完成 Apple 官方公证。初次启动需要用户在系统安全设置中单次放行。
2. **Nikon Z8 / Z9 HE/HE* 高效率压缩 NEF 解码限制**：受限于底层开源解码器支持进度，目前尚无法原生读取高效率压缩格式，需使用 Adobe DNG Converter 转码。
3. **老旧非主流扫描仪专有格式兼容性**：全球各类中古扫描仪厂商众多，极少数老式专有格式（如某些罕见工业分光仪的专有格式）仍在持续扩展测试适配中。
4. **暂未提供官方预编译的 Linux GUI 发行版**：虽然核心 Rust 引擎与色彩管线具备完备的跨平台编译能力，但当前阶段官方发布的安装包主要聚焦于 Windows 与 macOS。
5. **源片只读引用机制下的脱机敏感性**：移动硬盘拔出或文件夹重命名会导致画面暂时脱机，需通过“定位文件”功能重新绑定路径。
6. **硬件校正工作流的实验性状态**：顶栏中的“硬件校正”模块涉及高难度光谱拟合算法，目前仍定性为实验性功能，其交互与参数模型在未来版本中仍可能持续演进。
