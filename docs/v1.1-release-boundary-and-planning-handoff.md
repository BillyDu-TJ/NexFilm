# NexFilm v1.1.0：技术脉络、发布边界与后续路线

> 更新时间：2026-09-07  
> 用途：供项目负责人审阅，也供下一次“理论与规划”对话接手。本文记录产品和技术决策，不作为当前工程任务的直接修改指令。

## 写在前面

NexFilm v1.1 的重构已经持续了一段时间。我们从最初的“解决通道溢出”，逐步讨论到 RAW 数据域、硬件校准、胶片密度、片基与片头、数字 mask、Status M 和胶片特性曲线。理论框架比 v1.0.2 完整了许多，代码也搭起了新的校准骨架。

现在最重要的工作是收束。

项目计划在一周内完成 v1.1.0 的发布准备。这个版本应当成为一条新的稳定起点：普通用户导入照片后仍能一键得到自然、可编辑的正像；愿意校准的用户可以得到更稳定、更可追溯的结果；软件对每条路径的能力边界有诚实说明。数字 mask、完整的密度标准化和胶片曲线反演则按数据条件逐步加入后续版本。

可以把 v1.1.0 的目标概括为：

> **先让新的管线既好用又说得清，再让未来版本越来越接近可验证的胶片测量。**

本文同时保留早期讨论形成的技术形态和产品设计，避免后续对话只看到当前代码，而忘记这次重构最初要解决什么。

## 当前交接结论（v1.1.0 收束）

v1.1.0 的核心是可解释、可追溯的基础密度/校准主干：dark/open 相对透射率、基础 Capture Correction、D-min/D-max 与 Content Range 分离、Profile 持久化恢复，以及 Characterized fit 的受校验应用。Smart Auto / ProPhoto Estimate 是没有可用校准资料时的正式 fallback，Loose Import 继续保持旧版 Smart Auto 兼容行为，但 Smart Auto 不是 v1.1.0 的校准核心。

当前实现没有声称完成完整胶片科学模型。Density Calibrated、物理 Status M、数字 mask、完整 ICC 扫描模型、flat 应用和胶片 H-D / Film Profile 继续延期；Capture Corrected 与 Capture Characterized 保持 experimental/default-off，直到真实硬件素材和独立测量完成验证。代码路径和合成数据合同已完成，真实设备端到端验证仍待完成。

文档中的 ProPhoto Estimate、Estimated Base 和显示端锚点均是工作流估计或显示参考，不是经过物理测量的绝对密度。只有带明确参考域、设备条件和独立验证报告的后续 Density 层，才可以使用绝对密度表述。

## 一、我们为什么重构数据管线

v1.0.2 已经能够完成日常负片反相，而且在许多普通素材上有不错的观感。它的问题主要出在数据的物理含义不够清楚：LibRaw 完成显影后，图像又经过相机矩阵、sRGB 相关处理和旧的 Status M 拟合矩阵，多个步骤混在一起。最终结果可以好看，却很难解释其中的数值究竟代表相机信号、工作空间 RGB，还是胶片密度。

v1.1 最初从一个具体故障开始：某些高动态范围相机在颜色变换过程中发生通道截断。把解马赛克后的运算改为 f32，确实可以避免中间量被 u16 截断。但后续讨论让我们认识到，f32 只是一个数值容器。它能保留负值和超范围值，却不会自动赋予这些数值正确的物理含义。

因此，v1.1 真正要解决的是两个问题：

1. 保留足够完整的数值信息，让转换过程稳定、平滑，避免溢出和断层。
2. 把“经验反相”和“可测量校准”分开，让每一种结果都有清楚的来源和承诺范围。

这也是为什么旧的 sRGB Status M 矩阵没有直接迁移到新管线。它可以继续服务于 Legacy 外观复现，但不能跨越到 Camera Native RGB、ProPhoto RGB 或任意扫描仪 RGB 后仍被解释为同一个物理校正。

## 二、v1.1 形成的技术形态

### 1. LibRaw 保留，但职责缩小

我们不打算自行维护各厂商 RAW 格式，也没有必要抛弃 LibRaw。合理的分工是：LibRaw 继续负责识别和解开 RAW 文件，NexFilm 接管真正影响校准含义的数学过程。

```text
LibRaw
  文件格式识别、厂商压缩解码、CFA、活动区域、黑白电平、
  masked pixels、方向、ISO/曝光、相机标识和缩略图

NexFilm
  dark/open/flat 校正、质量掩码、固定解马赛克、
  Capture Separation、透射率、密度和胶片重建
```

相应的代码边界在早期设计中被概括为：

```text
decode_raw_mosaic()       -> RawMosaic + RawMetadata
decode_smart_auto_rgb()   -> CameraRgbEstimate
decode_measured_input()   -> DensityInputRgbF32
```

`dcraw_process` 仍可用于兼容性优先的 Smart Auto。它的输出已经包含黑电平、通道增益、白平衡、解马赛克和相机色彩转换，所以应被称为图像估计，而不是原始传感器响应。

### 2. 两条路径服务不同用户

v1.1 的内部结构保留两条路径，但用户最终仍然只需要点击同一个 Auto Invert。

```text
Smart Auto
RAW -> LibRaw processed RGB -> 宽色域图像估计
    -> 自动中和与内容分析 -> 正片显示

Measured Capture
RAW -> LibRaw unpack -> 原始 CFA
    -> dark/open/flat -> 固定解马赛克
    -> Camera Native RGB -> Capture Separation
    -> 正值透射率 -> 密度与胶片处理
```

Smart Auto 的职责是兼容、稳定和好看。Measured Capture 的职责是增加设备校正、重复性和可追溯性。前者属于经验反相，后者逐步接近测量管线。两条路径的价值不同，并不存在“普通用户的结果就是错误结果”这种关系。

### 3. 校准分成 Capture、Density 和 Film 三层

早期讨论中最重要的架构决定，是把校准拆成三个位置明确的层。

| 层 | 它回答的问题 | 典型输入 | 典型输出 |
| --- | --- | --- | --- |
| Capture | 这套相机、镜头和灯板如何读取胶片 | RAW、dark、open、flat、透射目标 | 校正后的线性透射率通道 |
| Density | 这些通道如何对应某种明确的密度标准 | Status M、printing-density 或其他密度参考 | 可比较、可验证的密度 |
| Film | 这种胶片的密度如何还原为正片 | 胶片型号、乳剂、冲洗条件、曝光阶梯 | 正片曝光和颜色 |

它们在管线中的顺序如下：

```text
RAW mosaic / scanner RGB
  -> 输入识别与元数据
  -> dark / open-gate / flat / 坏点 / 饱和处理
  -> Camera Native RGB
  -> Capture Separation
  -> 正值 Density Input RGB 透射率 T
  -> D = -log10(T)
  -> 片基 D-min 扣除
  -> Density 标准化与数字 mask
  -> 胶片特性曲线反演
  -> Positive Linear ProPhoto RGB
  -> 曝光、影调、LUT、显示与导出
```

这里有一条必须长期保留的数学边界：

```text
-log10(Ax) != A[-log10(x)]
```

矩阵放在 log 前还是 log 后，会改变它所代表的物理过程。一个普通颜色矩阵即使效果很好，也不能因为采用 f32 或 ProPhoto 就自动成为密度校正矩阵。

### 4. DCP、色卡、IDT、Status M 和数字 mask 分别做什么

这些方法都在“减少设备与目标之间的偏差”，所以外观看起来相似，但它们通常服务于管线中的不同位置。

| 方法 | 常见位置 | 实际作用 |
| --- | --- | --- |
| DCP 或相机 Profile | log 前 | 把相机 RGB 转到标准颜色空间，处理相机响应和白平衡 |
| 24 色卡、IT8 或其他目标 | 取决于参考值的定义 | 用已知色块拟合设备到目标空间的变换 |
| IDT | log 前 | 将相机或扫描仪输入变换到 XYZ、ACES 或其他标准输入空间 |
| Status M | 密度测量定义 | 规定使用怎样的光谱响应来读取胶片密度 |
| 数字 mask | log 后 | 补偿扫描设备与目标印相条件之间的染料通道串扰 |

色卡本身并不决定校正属于哪一层。IT8 的 Lab 数据适合做颜色 Profile；明确的 Transmission RGB 可以拟合 Capture Separation；来自密度计的 Status M 数据才适合建立对应的密度校正。关键始终是参考值的物理定义。

这些步骤也可以串联：先通过 IDT 或 Capture Separation 规范化采集通道，再进入密度域，随后使用 Status M 或 printing-density 参考拟合数字 mask。把它们全部压缩成一个“通用去色罩矩阵”，会失去适用范围和可验证性。

### 5. f32 与 ProPhoto 的正确位置

v1.1 采用 f32，是为了保存运算范围并减少中间量化。Linear ProPhoto RGB 是很合适的正片工作空间，也可以作为 Smart Auto 的宽色域图像载体。

它并不是天然的胶片密度输入。ProPhoto RGB 来自通道混合，可能包含负值和大于 1 的值；对它直接应用物理透射率公式，只能视为经验算法的一部分。Measured 路径必须从原始 CFA 和同构参考建立正值透射率，再进入 `-log10`。

## 三、早期确定的产品和功能设计

### 1. 一份 Profile，一次配置，自动选路

用户面对的产品对象是一份 Calibration Config Profile，而不是三套彼此独立的矩阵文件。Calibration 页面引导用户提供现有素材：相机和灯板信息、dark、open-gate、flat、透射目标以及其他参考。缺少某项素材时可以继续创建，软件在相应环节采用默认路径。

引擎内部保留三层能力：

```text
Capture: Default | Corrected | Characterized
Density: Estimated | Aligned | Measured
Film:    Generic | Approximate | Inverse
```

这三层分别判断，最后在界面上汇总成一个简洁状态。Profile 里有 dark/open，只能说明 Capture 得到校正；加入目标 patch 并通过验证后，可以进入 Capture Characterized；Density 和 Film 仍需要各自的参考资料。

日常工作时，用户为当前 Roll 选择 Profile，然后点击 Auto Invert。引擎检查 Profile、参考文件、算法版本和输入条件，选择当前能够成立的最高路径。若某一层失效，处理继续进行，同时在报告中保留具体原因。

### 2. 三类用户的使用方式

| 用户 | 可提供的资料 | 软件采用的路径 | 结果定位 |
| --- | --- | --- | --- |
| 普通用户 | 一张照片和 Film Area | Smart Auto | 自然、稳定、便于编辑的经验性正像 |
| 进阶用户 | 固定翻拍架、dark/open/flat、透射目标 | Capture Corrected / Characterized | 更好的跨帧一致性和设备可追溯性 |
| 研究或档案用户 | 窄谱/多波段光源、SPD、密度目标、曝光阶梯 | Density 与 Film 层 | 可验证的密度和胶片模型 |

最初的产品原则一直很明确：校准等级提高的是准确性、重复性和解释能力。Smart Auto 依然是正式产品路径，它不需要以“科学测量”作为存在价值。并且，对于用户来说，软件采用什么级别、什么校正管线是透明的。他们可以在专业的角度上知晓软件的处理方式，但在使用上一定是通过共同的"Auto Invert"按钮实现反相。用户前期创建好校正Profile后，使用时只需点击按钮，无需过多操心。

### 3. Calibration 页面的交互形态

Calibration 与 Library、Develop、Rolls 并列，用来建立和管理 Profile。早期 UI 设计采用双栏结构：左侧列出已有 Profile，右侧展示所选 Profile 的详情和一条纵向管线。每个节点以简单状态说明当前使用校正、默认实现、实验能力或需要重新验证。

矩阵、条件数、训练与验证误差、参考文件摘要和 digest 放在可展开的 Technical Report 中。Develop 页面只保留 Roll 级 Profile 下拉框和简短状态，日常反相继续由一个 Auto Invert 按钮完成。

Profile 的记忆规则也已经确定：每个 Roll 保存自己的选择；last-used 只作为以后新 Roll 的默认值；更改全局默认不会追溯改变已有 Roll。Profile 暂时不可用时保留绑定，以便用户恢复原始参考后重新启用。

### 4. D-min、D-max 与 Film Area 的交互

Film Area 只描述照片的几何和内容区域。它负责裁切、透视、旋转以及排除齿孔、白色灯板和其他背景。它不再承担密度端点的定义。

D-min 来自未曝光片基。D-max 来自全曝光片头、控制条或其他明确参考。照片本身的最亮和最暗部分只能描述 Content Range，因为雾天和中短调照片可能既没有纯白，也没有纯黑。

因此，Auto Invert 内部需要分别处理：

```text
Density Anchors：片基和全曝光参考建立的物理坐标
Content Range：当前照片实际使用的影调范围
Render Mapping：将照片放到可观看范围的曝光和影调映射
```

135 胶卷通常较容易保留片头和片基；120 很难获得可靠片头，适合使用片基、独立参考或 Film Profile；Loose Import 默认采用内容估计。三种导入方式共享同一个数据模型，仅参考资料的完整程度不同。

## 四、当前实现到了哪里

### 1. 代码状态

截至 2026-09-08，项目位于 `codex/smart-auto-p0-fix` 分支。当前收束基线是本轮完成后的 HEAD（Smart Auto P0 与 resolver 收束提交）。

其后已经连续提交多次 Smart Auto 修复；发布前必须以本轮完整验证结果为准，不再沿用旧的测试数量或工作树状态描述。

### 2. 已经接通的部分

目前代码已经具备以下基础：

- LibRaw 解包后的 RawMosaic 和较完整的 RAW 元数据合同；
- dark/open/flat、CFA 质量标志和固定 Bayer 解马赛克；
- Smart Auto 与 Measured Capture 两条真实影响像素的路径；
- Roll 级 D-min/D-max 锚点、来源、置信度和失效检查；
- 版本化 Calibration Profile、参考摘要、digest 和验证报告；
- 用户目标 patch 到 `CaptureSeparation3x3` 的拟合和应用；
- 独立的 Scanner Input Profile，并能作用于预览和导出；
- Calibration 页面、Roll 绑定和失效回退的产品骨架。

这些工作证明新架构能够运转，也为真实校准保留了入口。

### 3. 仍需真实材料验证的部分

项目目前没有完整的相机、灯板、dark、open、flat、透射目标和独立密度计素材组。因此，现阶段可以验证计算链路和数据合同，却无法证明 Capture Separation 在真实设备上的绝对精度。

固定 Bayer 解马赛克已经存在，X-Trans 仍走 Smart Auto 回退。macOS 原生 LibRaw ABI、常见相机格式矩阵以及真实大型 RAW 的速度和内存表现，也需要在后续验证中补齐。

Scanner Profile 当前主要是 NexFilm 自定义 JSON 变换。正式支持互联网下载的 ICC 或厂商配置，还需要处理文件来源、许可、输入编码、扫描软件设置、PCS/XYZ 目标和硬件指纹匹配。单纯找到一个同型号扫描仪 Profile，并不能保证它适用于当前扫描文件。

### 4. 当前最重要的回归

用户提供的散片截图显示：没有片基、片头和校准文件时，自动选择 Film Area 后直接反相，画面出现明显青绿偏色、过暗和反差不足。v1.0.2 在同类场景中可以正常工作，因此这是 v1.1.0 发布前必须解决的 P0 问题。

目前的分析指向三个相互关联的原因：

1. 片基估计曾从整张代理图取高百分位，白色灯板可能被当成片基。
2. Preserve Tone 使用固定最小密度跨度，却缺少合适的中间调重定位，短跨度照片因此整体偏暗。
3. Smart Auto 以 ProPhoto Estimate 近似执行密度运算，输入中的负值、超范围值和通道混合需要更稳健的经验反相设计。

当前分支正在处理这些问题。这里的判断标准很简单：没有校准资料时，软件仍应给出曝光合理、色彩自然的正像；物理端点未知只影响结果的科学承诺，不影响基本可用性。

## 五、v1.1.0 应该发布什么

v1.1.0 的主题应当是“稳定且诚实的新管线”。它不需要一次完成整套胶片色彩科学。

| 能力 | v1.1.0 决定 | 发布要求 |
| --- | --- | --- |
| Smart Auto | 正式功能 | 无参考散片必须正常反相，达到或超过 v1.0.2 的基本观感 |
| Film Area | 正式功能 | 几何、片基候选和内容分析使用同一坐标合同 |
| Roll 密度锚点 | 正式功能 | D-min/D-max 来源清楚，Content Range 不覆盖物理端点 |
| Preserve Tone | 正式功能 | 短调关系得以保留，中间调保持可观看 |
| Calibration Profile 管理 | 正式功能 | 创建、保存、绑定、失效提示和回退可靠 |
| Capture Corrected | 实验功能 | dark/open 等素材实际参与像素计算，状态明确 |
| Capture Characterized | 实验功能 | 目标 patch 拟合实际生效，报告验证误差和适用范围 |
| Scanner Input Profile | 实验或隐藏 | 仅在输入域明确时应用，避免误处理普通 JPEG/TIFF |
| Density Calibrated | 后续版本 | 等待明确密度参考和真实材料验证 |
| 数字 mask | 后续版本 | 等待胶片、设备和目标 printing density 数据 |
| H-D 曲线反演 | 后续版本 | 等待曝光阶梯、胶片和冲洗条件数据 |

### v1.1.0 的最低用户体验

普通用户导入一张照片，确认 Film Area，点击 Auto Invert，即可进入正常的正片编辑状态。自动分析可以使用内容估计，但分析结果应留在显示层，不能写成实测的 D-min 或 D-max。

有片基时，软件优先使用片基建立更稳定的通道基准；有全曝光参考时，再建立完整端点；有 Calibration Profile 时，Capture 层进一步提高设备一致性。整个过程对用户保持透明，只在状态摘要和技术报告中说明实际采用的路径。

### v1.1.0 的科学表述

发布文案可以使用以下层级：

- Smart Auto / ProPhoto Estimate
- Capture Corrected Experimental
- Capture Characterized Experimental
- Scanner Input Estimate / Characterized

“Density Calibrated”“Status M Calibrated”和“Film Inverse”应留给后续有参考数据和验证报告的实现。

## 六、合并回 main 的门槛

当前分支适合在 Smart Auto P0 完成后进入发布候选，而不是按功能数量或测试数量决定合并时机。

发布候选至少需要通过四组验收。

### 使用体验

- 无校准的 Loose Import 可以稳定得到正像。
- Film Area 外白色灯板的大小和亮度基本不影响照片区域。
- Film Area 包含或不包含少量片基时，画面没有剧烈偏色或曝光跳变。
- 雾天、低反差和中短调照片保持原有影调性格，同时拥有正常中间调。
- Auto Invert 仍是一键操作。

### 数据语义

- Physical D-min/D-max、Estimated Base、Content Range 和 Render Mapping 分别保存和报告。
- Smart Auto 的估计值停留在估计层。
- 无效、饱和、负值和不一致参考会触发质量标志或回退原因。

### 回归与一致性

- 135、120、Loose Import、短调照片和白灯板背景都有可重复样本。
- 同一素材完成 v1.0.2 与 v1.1 的视觉 A/B。
- Preview、缩略图、CPU、WebGL 和导出结果使用一致的数学合同。
- Rust 测试、UI 契约脚本、格式检查、diff 检查和发布构建全部通过。

### 安全回退

- Profile 丢失、参考文件变化或输入条件不匹配时，当前 Roll 可以继续通过 Smart Auto 工作。
- Roll 保留原 Profile 绑定和失败原因，参考恢复后可重新验证。
- 实验性 Capture 和 Scanner 功能不会阻断普通工作流。

完成这些验收后，可以从当前分支建立 v1.1.0 release candidate，再合并到 `main`。在此之前，校准页面和矩阵拟合完成得再多，也无法替代 Smart Auto 的基础体验。


## 八、1.1 之后的路线

### v1.1.x：用真实素材把骨架做实

这一阶段重点收集相机、镜头、灯板、dark、open、flat、透射目标和扫描仪样本，完成 Calibration Session/Validator。需要验证 CFA 相位、活动区域、坏点、饱和、参考一致性和跨平台 LibRaw 行为。

Calibration 向导也适合在这一阶段完善：自动检查参考图、生成质量报告、管理 Profile 导入导出、提示校准漂移，并支持批量 Roll 复用。Scanner Input 则补齐 ICC、输入编码和设备指纹，形成可靠的扫描输入边界。

### v1.2：Measured Density 与数字 mask

当 Capture 输入已经通过真实验证，且项目拥有明确的密度目标数据后，可以建立 Density 层。第一批功能可以包括 Status M 或其他已定义密度参考、printing-density 转换、受约束的密度矩阵和胶片相关数字 mask。

这类模型需要保存胶片、冲洗、设备、光源和目标标准，并报告验证误差、矩阵条件数、噪声放大和有效密度范围。Profile 超出适用范围时应回到相对密度或 Smart Auto。

### v1.3：Film Profile 与 H-D 曲线

严格的胶片特性曲线需要曝光阶梯或 sensitometric wedge，并绑定胶片型号、乳剂批次、冲洗条件和采集基准。逐通道曲线应保持单调可逆，明确趾部、直线段和肩部，并使用留出的曝光档验证。

数字 mask 和密度分离应先完成，再进入 H-D 反演。用于观感的 S 曲线和 LUT 继续留在显示层，避免与胶片物理模型混在一起。

### 更远期：窄谱和多光谱

RGB LED 分时采集、SPD 管理、多波段分离和连续光谱属于研究型能力。它们可以提高密度层的可解释性，但也需要更严格的噪声、漂移和硬件一致性控制。等 v1.2 的密度数据模型稳定后再展开，会比现在直接增加硬件分支更稳妥。

## 九、下一次理论与规划对话的重点

下一次对话应围绕几个真正影响产品路线的问题展开：

1. 为 Smart Auto 定义最终的经验反相域，使“没有片基也能得到好图”和“避免冒充物理密度”同时成立。
2. 决定 Capture Characterized 在真实硬件验证前的公开程度和用户文案。
3. 决定 Scanner Profile 在 v1.1.0 中作为实验入口发布，还是先隐藏到 v1.1.x。
4. 为 v1.2 选择第一个可验证的 Density 目标：Status M、printing density，或一套明确记录的自有参考。
5. 规划数字 mask 所需的胶片、设备和参考数据集，避免再次以通用矩阵替代实验数据。
6. 定义 Film Profile 的采集规范，让 H-D 曲线从一开始就绑定胶片、冲洗和密度基准。

这些是理论和产品规划问题。当前工程对话只需要继续完成 Smart Auto P0、回归测试和 v1.1.0 发布准备。

## 最后的路线判断

v1.1.0 的价值不在于提前实现所有色彩科学，而在于建立一套可以继续成长、同时不牺牲日常使用的基础。

```text
v1.1.0
  稳定的 Smart Auto
  + 正确的 Film Area 与密度锚点语义
  + 可追溯的 Calibration Profile
  + 明确隔离的实验能力

v1.2
  真实参考支持的 Density Calibration 与数字 mask

v1.3
  胶片和冲洗条件绑定的 Film Profile 与 H-D 曲线
```

当前路线应从“继续增加校正点”转回“完成 Smart Auto、建立发布证据、交付 v1.1.0”。只要这一点守住，现有校准骨架就不会浪费，未来的科学功能也会建立在更稳固的产品基础上。
