# 统一密度管线（本轮改动记录）

本轮把「输入类型选择整套密度数学」改为「输入类型只选择输入域」，并给出逐张样本的量化对照。

## 一、统一后的实际调用链

```
文件 → 解码器选择（后缀/容器，只决定解码路径）
     → resolve_input_domain(path, scanner_profile)      ← 唯一允许分叉的一步
        1) 内嵌 ICC → 基色 + 传递曲线（Verified）
        2) 扫描仪 Input Profile / 扫描仪容器记录（Flextight plist 的
           RGBProfile + Gamma，Verified；读不到则用文档默认值 + estimated）
        3) RAW/DNG 元数据（CameraNative + CameraRaw；LinearRaw 扫描仪 DNG 单独识别）
        4) 扫描仪机型识别（Documented default）
        5) 兜底按 sRGB 解释并标 estimated
     → 统一工作域：ProPhoto 线性 f32（不经 u16 线性 sRGB 中转）
     → 统一密度域：逐通道减片基 → D = -log10(T) → 显示窗口
       a) 测到过片基（含被质量判据拒绝的，见第十一、十二节）：逐通道同像素
          端点，channel_offsets 恒为 0；没有可信片基的帧再做片基落点均衡
          （窗口规则 5）
       b) 连片基都没测到：三通道共用一个跨度 + 每通道 ±0.20 D 的原点偏移
     → 显示映射：ProPhoto→sRGB → gamma/LUT
```

三条业务路径的差别只在**输入端与片基来源**，密度数学完全一致：

| 场景 | 片基来源 | 显示窗口 |
| --- | --- | --- |
| 按卷导入 + 完整标定 | 采样片基 + 采样片头（物理锚点） | `offset + span[i] × highlight`，逐帧 offset 只做整体位移 |
| 按卷导入 + 未标定 | 该帧 Film Area 内的片基估计（片边窄带，其次膜面低密度尾部） | 逐通道同像素端点（见第十一节） |
| Loose Import | 同上 | 同上（与上一条必须逐像素一致） |

输入域记录随帧持久化在 `PipelineProcessingReport::input_domain`，并出现在技术报告中。

### 3.1 散片默认几何（无 Film Area）

目标文档引用的 5.3-1 基准（R/G 1.028、B/G 0.774）是散片默认几何口径。上一版文档里的同几何表是**在已被移除的显示曲线下**测得的，不再代表当前代码；需要时用 `NEXFILM_REPORT_NO_AREA=1` 重跑，不要沿用旧数字。

### 3.2 几何稳定性（新发现，需后续处理）

自动片门检测对解码尺寸不稳定：同一个 `_DSC7571-Pano.tif` 在 1024px 得到覆盖大半画面的四边形、1200px 得到 fallback（无片门）、1600px 得到一个仅覆盖右下角的退化四边形。片基与窗口随几何变化，渲染结果随之变化。生产流程用的是固定导入缩略图（几何稳定），但用户确认的 Film Area 质量仍是散片结果的主要不确定性来源。

## 四、迁移与失效

- `migrate_retired_density_recipe` 在 `init_db` 中执行：凡带 `legacy_linear_srgb` 且不是 LegacyV1 的记录，一律改到 `linear_prophoto_estimate`，`compatibility_base` 重置为 `unresolved`，`base_color` 与 `rendered_thumb_base64` 清空，并记录 `retired_density_recipe_migrated` 回退原因；重复执行不再命中。
- LegacyV1 老工程（`contract = legacy_v1`）完全不动。
- `is_smart_auto_compatibility` 保留为只读支持：新代码不再写这个标记，迁移后不再有帧命中它。

## 五、仍未解决的问题

1. **宽色域拼接 TIFF：已由有界通道跨度响应解决（`_DSC7583` / `_DSC7569` 达标）**。这三个 `lr合并\*Pano.tif` 的红通道在文件里只剩绿通道 1/4–2/3 的密度跨度，一个三通道共用的窗口必然把红压在半程以下（R/G 0.018–0.093）。现在保留共用窗口原点（片基仍是中性参考），只让每个通道按自己测得的跨度分配窗口宽度：`g_i = clamp(span_i / luma(span), 1/上限, 上限)`（上限通常 1.35，跨度比超过 2.0 判为上游截断通道时放宽到 3），死区 1.15×、1.35× 处取满，等价于把窗口按响应做 `density / gain`，片基（密度 0）在三个通道仍落在同一显示值。跨度用**逐通道 2%–98%**（`measure_content_channel_spans`）测量：窗口端点仍保持同像素，而响应测量必须看到"某通道的极值不与画面亮度对齐"的情况，否则 `_DSC7583` 这种红通道塌陷会被低估（同像素端点测得 3.70×，逐通道测得 4.26×）。`_DSC7583` 现为天空浅蓝带白云、混凝土近中性、草地暖褐，与 LR+NLP 参考一致。**与已被移除的「逐通道显示响应曲线」的区别**：那一版是显示阶段额外加的一条逐通道曲线，对所有帧无条件生效，改掉了相机 RAW 已认可的观感；本版按死区斜坡生效，且原点共享、片基仍中性。正常素材（哈苏 FFF ×5、尼康扫描仪 TIFF ×4、Epson／精益 DNG ×6、尼康 NEF ×3、诺日士 JPEG ×3）实测失衡比 1.03–1.49，增益上限 1.35×，属于有界修正而非自由缩放。
2. `_DSC7571-Pano.tif` 只改善了一部分（R/G 0.093 → 0.372）：它在工作域里的失衡比只有 2.12，红通道的缺陷更多体现在**电平**而不是跨度（扣片基后的中位密度 R 0.196 / G 0.337 / B 0.580），而电平对齐正是被否决的灰世界操作。它同时也是这一批里唯一在离线 harness 里**没有检出片基**的一帧（几何 fallback），片基退化为「画面内最亮分位」（置信度 0.499）。要彻底解决它需要更稳健的片基/几何（第三节 3.2 已记录自动片门对该文件不稳定），或对"电平型"失衡另立判据。
3. 通道贴顶：`任务 _1233.fff` 蓝 33.3%、`_DSC7333.NEF` 红 23.5%、`任务 _1343.fff` 约 45%（该帧在 v1.0.2 下同样是 45%）。这些帧的失衡比都在 1.4 以下，通道响应补偿按设计不介入；端点与画面分布的固有问题仍需 H-D 反演/胶片响应模型（§九列为后续版本）。
4. 扫描仪 TIFF 的 B/G 略低于同几何的 v1.0.2（5.3-1：0.685 对 0.715，约 −4%），R/G 略高（1.123 对 1.030）。文档基准 0.774 是在「散片、无 Film Area」几何下测得的，与本表的自动片门几何不可直接比较；两套口径的数值都在上表可复现。
5. 扫描仪 FFF 的容器记录只解析 `RGBProfile` / `Gamma`；FlexColor `ImageCorrection` 的阴影/高光端点未使用，记录读不到时仍是文档默认 1.8 + sRGB（标 estimated）。
6. 卷级 Roll Anchored 路由不受本轮影响：端点来自采样锚点，显示窗口宽度本就 ∝ 每通道物理跨度（`density_high[i] = offset[i] + span[i] × highlight`），等价于已经按物理响应做过逐通道斜率归一，因此不再叠加内容增益。同理，`prepare_content_render_limits` 的 `calibrated_span` 分支保持原样。Loose Import 与未标定 Roll 走的是同一条内容窗口分支，两者都在本轮覆盖范围内。
7. 内容对齐偏移上限收紧到 0.20 后，无可用片基的帧（`无法反相.fff`、`5.3-4.tif`、`_DSC7571-Pano.tif`）走画面内容对齐，仍可能有轻微残留偏色。

## 八、本轮修复（三条业务路径的偏色）

问题现象：场景 2（未标定卷）与场景 3（散片）在这一批真实素材上都有肉眼可见的偏色，而且**同一卷不同帧的颜色各不相同**；场景 1（完整标定卷）表现正常。三处根因与修复：

1. **窗口原点被逐通道平移**（`prepare_content_render_limits_with_spans`）：有片基的分支一度改用了带内容对齐偏移的 `share_smart_auto_density_scale`（偏移上限 0.20 D），把「密度 0 = 片基」的显示值按通道拆开——片基本身被染色，而偏移量来自画面自己，所以偏色随画面内容变化。现在恢复 `share_smart_auto_density_scale_without_offsets`：有片基时 `channel_offsets` 恒为 0。
2. **逐通道跨度响应的死区过宽**（`CHANNEL_RESPONSE_BALANCED_RATIO`）：真实扫描的三层响应差一般在 1.1~1.8×，旧死区 1.6× 使绝大多数帧从不补偿，三通道只能共用一个跨度，短通道永远到不了白点。死区降为 1.15×、满额 1.35×、上限 1.35×（上游截断通道 3×）。该补偿按 `density / gain` 缩放且原点是共享的，片基仍落在同一显示值。
3. **片基判据太松**（`FILM_BASE_BAND_AGREEMENT`）：片边窄带与膜面低密度尾部原本允许相差 0.25 D 就算互相印证，而 0.2 D 的片基误差本身就是一次可见偏色。现在只允许窄带**不得比尾部更暗超过 0.05 D**（片基是底片密度最低处，画面内不可能比它更透），方向单向收紧；一旦越界就退回膜面尾部候选。
4. **老工程的一次性重算**：帧的显示端点随帧持久化，所以用旧规则分析过的场景 2/3 帧不会自己更新。`PipelineProcessingReport::analysis_window_rule` 记录端点是用哪一版窗口规则推导的（旧记录反序列化为 0），`frame_needs_window_reanalysis` 让这类帧在下次自动反相时重新推导一次；完整标定卷（`RollAnchoredDirectInvert`）与采集校正（`CaptureCorrectedV11`）不受影响，端点仍只来自采样锚点。用户对这一类帧执行一次「自动反相」即可，之后可用复制/粘贴把参数广播给整卷。

回归证据（`cargo test --lib` 224 项、`scripts/verify-*.cjs` 11 项、`cargo fmt --check` 全过）之外，新增断言把「曝光/高光/阴影/全局 D-Min/D-Max 不得引入偏色」这条钉住：

- `tone_controls_never_tint_a_neutral_print`：主曝光、高光、阴影、全局 D-Min/D-Max 微调单独生效时，中性画面的三通道最大差 ≤ 4/65535，且每个控制与基线完全一致；
- `span_corrected_frame_keeps_its_neutral_axis`、`compressed_channel_recovers_its_display_span`：跨度补偿生效时片基与中性轴保持中性（合成样本 R/G 从 0.17 回到 1.00，片基显示值三通道完全相等）；
- `balanced_channel_response_keeps_the_shared_window`：三通道跨度一致的健康帧，窗口逐值不变。

三路径对照工具：`cargo test --lib three_pipeline_parity_report -- --ignored --nocapture`。它读取本机 `nexfilm_user.db` 中用户已确认的 Film Area 与 `rolls.json` 中已采样的片基/片头，对同一张照片分别渲染 P1（完整标定）、P2（未标定卷）、P3（散片）与 v1.0.2，断言 P2/P3 逐像素一致、片基显示值三通道相等，并把图片写到 `target/three-pipeline/`。

## 九、复制/粘贴的片基改为落在目标帧上重新测量

问题现象：把调好的单帧参数粘贴给同卷其他帧后，其中一部分帧出现明显偏色（片基本身被染色，偏色方向随帧变化），而源帧与另外一些帧正常。

根因：`apply_film_base` 原先把源帧的 `base_density` 原样写入目标帧。片基是**某一帧自己清片**的中性参考，而同一卷被分两次扫描/翻拍时记录到的片基密度可以差 0.15 D 以上。用真实素材（`G:\DCIM\755ND810`，Fujifilm C400，35 帧）复现：

| 帧 | 本帧实测片基 R/G/B (D) | 复制自首帧的片基 (D) | 用复制片基渲染 R/G | 用本帧片基 + 同一窗口渲染 R/G |
| --- | --- | --- | --- | --- |
| `_DSC7659` | 0.571 / 0.718 / 0.962 | 0.578 / 0.736 / 0.985 | 0.959 | 0.930 |
| `_DSC7660` | 0.677 / 0.741 / 0.823 | 同上 | **1.416（明显偏红）** | 0.990 |
| `_DSC7661` | 0.696 / 0.761 / 0.836 | 同上 | **1.407（明显偏红）** | 0.967 |
| `_DSC7662` | 0.701 / 0.768 / 0.855 | 同上 | **1.395（明显偏红）** | 1.045 |

修复（`choose_pasted_film_base`）：粘贴时按「① 在目标帧上重新测量 → ② 保留该帧自己已有的测量值 → ③ 才回退到复制值」决定实际使用的片基，并把结果回传给前端，使 WebGL 预览与后端状态使用同一个参考。目标帧的实测不可用时记录 `inherited_film_base` 并在界面上提示，不再假装它是本帧的测量结果（`base_is_frame_measurement` 同时要求标记与真实数值，默认半白 `BaseColor::default()` 不算测量）。

前端顺序也一并调整：先落地粘贴过来的胶片范围与密度范围，再准备代理并安装片基，最后用返回值刷新 `currentBaseDensity`，保证「测量所用的胶片范围」与「帧最终渲染的胶片范围」一致。

### 九.1 批量应用（只管物理设定：胶片范围与片基）

「批量应用」与「复制设置」是两条分工明确的路：批量应用把**胶片范围 + 片基**一起套到其他帧（弹窗里不再提供勾选，避免用户只套一半），复制设置才负责把调好的**显示端点**广播出去。因此批量应用不复制端点，也不再逐字复制源帧的片基，同时不在按下按钮时解码任何一张照片：

- **端点不动**：源帧的 `d_min / d_max / d_min_offset / d_max_offset` 不写入目标帧；目标帧的显示端点仍来自它自己的分析（或它自己接收过的复制设置）。
- **片基留白**：源帧的 `base_color` 只作为占位值写进那些**还没有自己测量结果**的目标帧，并把该帧 `pipeline_state` 里的 `base_source` 标记为 `inherited_film_base`（只改来源标记，目标帧自己的锚点、映射等一概保留）；已经有自己测量结果的帧连片基也不动。
- **就地重测**：帧第一次被解码时（Develop 打开、相邻帧预热、导出解码），`inherited_film_base_measurement` 按该帧自己的 Film Area 测片基并替换占位值（`install_film_base` 同时保持采样卷的显示映射 = 锚点 + 该帧自己的片基）。导出时若发现仍是继承片基，也在这条路径上测一次并回写，导出的文件不会印着别的帧的色罩。
- **状态不改**：批量应用只预处理数据，不改变"负片 / 已反相"的显示状态。打开一张照片永远保持它原本的状态，只有用户明确点击「自动反相」（或粘贴反相设置）才显示为正片；这条契约由 `scripts/verify-density-contract.cjs` 中"打开不得自行去色罩"的断言钉住。

因此批量应用是一个纯写库操作（`copy_settings_transaction` 不接触解码器），耗时与整卷解码无关；片基的测量成本被摊到每张照片本来就要解码的那一刻。契约见 `scripts/verify-density-contract.cjs` 中的「批量应用不得解码」「继承片基必须在解码处重测」两段断言，行为断言见 `src/batch_settings.rs` 的两个新测试。

## 十、逐通道响应补丁下线，窗口回到逐通道同像素端点（窗口规则 3）

### 10.1 走到这一步的过程

1. **规则 2（逐通道跨度响应）**：按「三通道内容跨度比」给每个通道分配窗口宽度（死区 1.15×、上限 1.35×）。它解决了 `lr合并\*Pano.tif` 的青/品红崩坏，但判据本身分不清「上游削平了通道」和「画面本来就以某色为主」，对正常素材写入了 90% 以上像素的改动。
2. **规则 3 第一版（输入域端点证据门）**：只在文件自身样本证明某个通道被削平（端点堆积 ≥15% 且 ≥5× 其他通道）时才补偿。它保住了 `_DSC7569`/`_DSC7583`，但**把所有正常素材推回了「共享密度跨度」这一步**，而那才是真正的问题所在。
3. **用户实测裁决**：只有 `任务 _1233.fff` 变好，富士 RAF、尼康 NEF、扫描仪 TIFF、诺日士 JPEG 等**全部变差**（RAF 出现紫蓝、NEF 明显偏绿）。同时明确：两张 LR 拼接的异常是**源文件问题**（LR 自动识别烘焙时裁掉了蓝通道），不属于软件问题，若为它们而影响正常照片就应当放弃该补丁。

### 10.2 根因：不是补偿，是「三通道共享一个密度跨度」

规则 2 的响应只是对共享跨度的一层修补。把三种窗口放在**同一批中性像素**上测量（`neutral_surface_window_comparison`，掩膜取自 v1.0.2 结果的亮中性像素），结论是决定性的：

| 样本 | v1.0.2 | 一个共享跨度 | 逐通道同像素端点（现在） |
| --- | --- | --- | --- |
| `DSCF0895.RAF` | 0.986 · 1.022 | 1.057 · **1.599** | 1.016 · 1.068 |
| `尼康nef_raw\_DSC7333.NEF` | 0.963 · 0.944 | **0.683** · 0.943 | 0.949 · 1.004 |
| `尼康扫描仪tiff\5.3-1.tif` | 0.933 · 0.964 | 0.891 · **0.673** | 0.960 · 0.991 |
| `诺日士jpg\000000070001.jpg` | 1.026 · 0.991 | **0.692** · 1.097 | 0.959 · 1.027 |
| `000021940005.jpg` | 1.017 · 1.014 | **0.685** · **1.309** | 0.990 · 1.151 |
| `精益黑白\raw0002.dng` | 1.002 · 1.018 | 0.934 · 1.164 | 1.006 · 1.026 |
| `哈苏fff\任务 _0866.fff` | 0.964 · 0.975 | 0.796 · 1.034 | 1.034 · 1.020 |

原因很直接：**不同采集路径的三通道响应本来就不同**（相机光谱响应 + 胶片三层 + 扫描仪通道增益）。把三者压到一个共享跨度上，等于把这种响应差直接变成偏色；而 v1.0.2 从来就是逐通道取端点（同像素选点，通道各取自己的值），所以它在正常照片上是中性的。规则 2 的「有界响应」只是部分重建了这个形状，所以它当时看起来「大体可用、偶尔偏色」。

### 10.3 本轮改动

1. **下线逐通道跨度响应**（连同端点证据门、`ChannelResponse`、`InputEndpointPileup`、`channel_response` 报告字段及其测试）。LR 拼接的异常按用户判定归入源文件问题。
2. **窗口恢复为逐通道同像素端点**：有可信片基时，`prepare_content_render_limits` 不再调用共享密度尺度，直接保留 `compute_content_limits_f32_with_bounds` 量到的每通道端点，`channel_offsets` 仍为 0（不做密度域平移）。
3. **最小跨度守卫修正**：旧守卫在任一通道跨度低于 0.8 D 时，会把**三个通道全部压成 0.8**，等于把逐通道窗口又抹平了。现在只对「塌缩」的通道按其自身中心加宽，下限降到 0.05 D（仅防止除零的退化窗口）。这一条本身就让 RAF 的中性面从 1.039 · 1.158 回到 1.016 · 1.068。
4. `DENSITY_WINDOW_RULE_VERSION` = 3：用旧规则推导过端点的帧，下次「自动反相」时重新推导一次。完整标定卷（`RollAnchoredDirectInvert`）与采集校正（`CaptureCorrectedV11`）不受影响。

### 10.4 实测

整卷一致性（`G:\DCIM\755ND810` 真实素材，`three_pipeline_parity_report`）：`roll_1789478298921_665` 的 `_DSC7654 / 7655 / 7656 / 7659 / 7660` R/G = 0.992 / 1.028 / 0.974 / 0.971 / 0.941、B/G = 0.887 / 0.893 / 0.973 / 1.042 / 1.047。同一卷在共享跨度下是 R/G 0.772 / 0.807 / 0.740（肉眼可见的偏绿），现在回到中性附近；P2（未标定卷）与 P3（散片）仍逐像素一致。

超采样诊断（`density_pipeline_sample_report`）：`_DSC7583` 由共享跨度的 R/G 0.018 回到 1.139、B/G 1.315；`_DSC7569` 由 0.004 回到 0.698、1.205——两张 LR 拼接不再崩坏，虽然它们仍是源文件缺通道的素材。

### 10.5 代价（需要知道的两点）

1. **片基不再逐像素中性**：逐通道端点意味着清片（片边、齿孔）会按各通道自己的显示电平成像，实测 spread ≈ 0.02（2% 显示量程）。v1.0.2 行为相同；这是换取正常照片中性的代价。若某天要求片边也绝对中性，只能改成「共享原点 + 逐通道跨度」，那是另一套形状，需要重新对全部素材做观感验证。
2. **整幅色偏被窗口吸收**：整幅加暖/加冷（透射率上的乘性变化 = 密度上的常量平移）会同时移动片基与各通道端点，因此打印结果几乎不变（`a_frame_wide_tint_is_absorbed_by_the_per_channel_window` 记录了这一行为）。v1.0.2 同理。要恢复对整幅色偏的响应，只能依靠物理锚点（整卷标定）或另立判据，不能靠内容窗口。

### 10.6 诊断与断言

- `neutral_surface_window_comparison`（`--ignored`，`NEXFILM_NEUTRAL_FRAME`）：同一批中性像素在 v1.0.2 / 一个共享跨度 / 逐通道同像素端点三种窗口下的读数，以及各窗口的端点与跨度打印。
- `visual_acceptance_v1_0_2_vs_v1_1`（`--ignored`）：把 14 张不同来源的样本渲染成「上=v1.0.2、下=当前构建」的对比图，写入 `target/visual-acceptance/`。
- `density_pipeline_sample_report`（`--ignored`）：逐样本打印输入域、片基、窗口、`[STAT]` 对照与 `[COMPARE]`（一个共享跨度 vs 逐通道端点的差异像素数）。
- 新增/改写的断言：`a_frame_keeps_its_own_co_sited_endpoints`、`a_short_channel_reaches_the_white_point`、`a_frame_wide_tint_is_absorbed_by_the_per_channel_window`、`partial_roll_anchor_keeps_content_derived_display_limits`；`prophoto_master_exposure_preserves_neutrality_with_channel_spans`、`linked_scanner_limits_preserve_co_sited_channel_bounds`、`one_roll_keeps_a_consistent_channel_ratio`、`input_class_and_provenance_never_change_the_density_mapping` 继续通过。

## 十一、被质量判据拒绝、但确实测到的片基不再被丢掉（窗口规则 4）

### 11.1 现象与定位

`test_picture\富士raf` 的 11 张（6×7 彩色负片、机内翻拍）整幅偏蓝：改动前整幅通道比 R/G 0.32–0.63、B/G 1.39–2.12。根因两条：

1. **实测片基被丢弃。** 这批文件翻拍欠曝约 4–5 档，片基只到满量程的 0.2–3%（蓝通道最低 0.17%）。它同时触发 `FILM_BASE_MAX_DENSITY = 1.60`（绝对密度）与 `FILM_BASE_MAX_CHANNEL_SPREAD = 0.75`（通道差）两道判据——两条都隐含"曝光正常"的假设。被拒后片基按 0 处理，该帧落到"共享跨度 + ±0.20 D 原点偏移"的兜底；而色罩的通道差是 0.3–0.5 D，装不进 ±0.20，于是片基在成品里落到 (0.30, 0.40, 0.79)——片基发蓝，整幅发蓝。
2. **估计器内部先丢了量。** `FilmBaseEstimate` 在被拒时把 `density` 直接置零，报告里因此分不清"测到了但被拒"和"根本没测到"。

### 11.2 改动

- `FilmBaseEstimate` 新增 `candidate`：无论判据是否接受，都保留该帧量到的片基；`density`（渲染实际使用的值）语义不变。
- `PipelineProcessingReport.film_base_candidate` 持久化该测量值。
- **显示窗口**：只要这帧确实测到过片基（含被拒绝的），就保留它自己的逐通道同像素端点，不再退到共享跨度兜底。同像素端点用同一批像素为三个通道取值，色罩的通道差已经在里面；实测该帧片基因此落在三通道 0.03 以内的同一显示值上，且不改变明暗。
- **证据判定** `prescribed_response_evidence`：为每帧记录窗口是否可信（`no_trusted_film_base`、`low_signal_channel`＝某通道基低于满量程 1%、`content_span_imbalance`＝三通道跨度比 > 2）。判定只进技术报告，**不改变渲染**；判定表由 `prescribed_response_evidence_report` 输出。
- `DENSITY_WINDOW_RULE_VERSION` = 4：用规则 3 推导过端点的帧重新推导一次；完整标定卷（`RollAnchoredDirectInvert`）与采集校正（`CaptureCorrectedV11`）不受影响。

### 11.3 实测（含后来推翻的读数）

- 整幅通道比（11 帧）：**0.32–0.63 / 1.39–2.12 → 0.80–1.30 / 0.96–1.11**。
- 作用范围（`prescribed_response_evidence_report` 逐帧窗口逐一对比）：只有这 11 帧的窗口变化；13 张 LR 拼接 + 29 个正常素材（扫描仪 TIFF、诺日士 JPEG、相机翻拍 NEF、哈苏 FFF、DNG）逐行完全一致。
- 渲染对照（`prescribed_response_render_report`）：2 张拼接、2 张扫描仪、2 张相机翻拍、1 张诺日士的 before/after **文件 MD5 相同**。
- **"11 张 RAF 的偏色消失"是当时基于整幅通道比的乐观读数，后被推翻**：以 Capture One 逐帧参照的帧均值为基准（`verify18.py`），11 帧中 5 帧到位（≤0.12），**6 帧转为明显偏红（0.23–0.39）**，用户判定失败。整幅通道比把随帧变化的偏色平均掉了——这是"整幅均值不能当中性判据"的又一实例。红帧的共同特征：同像素端点把红片基放到比绿片基高 0.05–0.10 个显示量程的位置。修复见第十二节（窗口规则 5）。
- 片基落点接近同一显示值（≤0.03）：由同像素端点近似保证，但如上所述并不足以让画面中性。

### 11.4 已知限制

- **观感差异**：这批 RAF 改动后比 Capture One 的成品更淡、反差更低。这是"无片基路径不套调色曲线"的固有观感（正常素材同样不套），需用户终审；要不要给这条路径配一条预设曲线是独立决定。
- **绝对残余测不准**：以 Capture One 成品为基准的中性面残余在多次测量中给出 0.18–1.7 的不同结果，取决于配准质量（互相关 0.61–0.88）、朝向、画幅裁切范围，以及"C1 自身是否把雾天天空中和"的观感选择。要给出可信的绝对线，需要场景中存在物理上确定中性的参照（灰卡等）。
- **LR 拼接那一族未改**：它们有可信片基、本来就往返通道端点，本轮规则不触及。实测其剩余误差是一个很小的逐通道密度偏移（约 R +0.015 D、B −0.014 D）；要定规则需要更多参照正片。
- **尝试过但撤销的两个方案**（都因测量否决，未留在代码里）：把窗口原点锚在实测片基上（偏色消失但 35–59% 画面被压成纯黑）；把白点改成逐通道分位（实测渲染逐字节不变，因为中性核内几乎没有截断）。相关脚本与读数在 `target\verify-0926\`。

## 十二、片基落点均衡：证据帧的逐帧中性化（窗口规则 5）

### 12.1 规则 4 失败后的第二轮调查（2026-09-27）

规则 4 留下的 6 个红帧需要解释：增益扫描证明让每帧回到参照所需的**跨度增益逐帧散布在 u_R 0.80–1.20**，任何常数处方都救不了。第二轮在 harness（`pooled_axis_report`）里系统试了四类"常数/固定"方案，全部被数据否决：

| # | 方案 | 思路 | 实测 | 结论 |
| --- | --- | --- | --- | --- |
| 1 | 全池化轴（原点色度+跨度比都按卷池化） | 处方替换内容估计 | 11 帧误差 0.16–0.46，多数比规则 4 更差 | 否决：欠曝帧对原点极度敏感，0.05 D 的原点改动就翻转观感 |
| 2 | 仅池化跨度比（原点保持同像素） | 只修响应形状 | 5 帧改善、6 帧恶化，无净收益 | 否决：帧均值由"原点×跨度"联合决定，各帧同像素误差互相抵消，替换单侧破坏抵消 |
| 3 | Status M 印片密度矩阵整体变换 | 用公开物理常数修响应 | 多数帧更红（0.10–0.68） | 否决 |
| 4 | 先验跨度归一化（26 张正常素材的跨度比包络） | 超包络的帧归一化 | **渲染不变**：数据与窗口围绕片基一致变换时，显示位置逐像素抵消 | 否决（机制无效，非数据否决） |

同时确立两条度量结论：C1 参照自身的逐帧帧均值散布 R/G 0.875–1.087（C1 有逐帧白平衡），固定规则不应也不可能逐帧精确匹配；判据应为"消掉测量误差后帧间收敛 + 肉眼中性"。

### 12.2 机制：片基落点均衡

真正起作用的逐帧量是**片基候选的通道差**——胶片自身的测量（片边/低密度尾部），不是场景内容。11 帧的候选通道差聚在 R−G −0.26…−0.33、B−G +0.38…+0.54（欠曝最浅的 4 帧内部 ±0.002），其逐帧**电平**误差是共模的（candidate − 内容最亮端 ≈ 每通道相等），色度是稳定的。规则 4 的同像素端点决定片基落在每通道显示量程的哪个高度，而红帧的红片基普遍比绿片基高 0.05–0.10 个量程——这个落点差就是红偏本身。

规则 5：对命中证据判定的帧，**把各通道"片基落点"均衡到 G 通道自己的落点**：

- 只动原点（`d_min`），跨度不动；每通道移动量 = span·(p_c − p_G)，红帧实测 0.02–0.05 D；
- 候选电平误差是共模的，均衡只用到色度；共模用窗口自身 luma 重新锚定，不产生新裁切；
- **落点为负的通道（候选比内容最亮端还亮 = 噪声底拾取）跳过不动**——浅欠曝 4 帧的 B 候选即属此类，跳过使它们完整保留规则 4 的好结果；
- **只对没有可信片基的帧生效**。可信片基在逐通道减除时已经用掉了自己的中性（片基恒在相对零点），其落点携带的是场景结构而不是片基颜色——对它们做均衡会把场景注入原点（实测 `_DSC7583` 的 B/G 因此被推高 1.236→1.297，已修正）。无可信片基时 `no_trusted_film_base` 证据必然命中，门槛自洽；
- `NEXFILM_RULE5_DISABLE=1` 可关闭均衡，供双跑对比。

### 12.4 已知限制与未决

- **1945 仍有红偏（0.241）**：它的片基落点本已均衡，红偏来自别处（增益扫描指向跨度 u_R≈0.90 的逐帧响应误差）。常数规则救不了；有界逐帧自动平衡（产品决策）是候选第二层。
- **观感偏淡**：与规则 4 相同的既有限制（无片基路径不套调色曲线），是否配预设曲线是独立决定。
- **LR 拼接族未解决**：唯一干净合并 `_DSC7587-2-Pano.tif` 的渲染为 R/G 0.778 / B/G 1.047，而同场景 C1 参照（渲染自被自动调整烘焙的孪生文件）为 R/G 1.038 / B/G 0.972。参照链被烘焙污染：C1 的胶片曲线可能恰好修正了烘焙，我们的轴模型忠实渲染干净源——哪个是"对的"需要对照真实场景判断。先验跨度归一化对该族渲染不变（12.1 #4），有界平衡也覆盖不了 0.26 的 R/G 差。此族的进一步动作需要产品决策。
### 12.5 打样响应 LUT（规则 5 之上的第二层）

帧均值指标掩盖了真正的观感差距：分亮度档对照（`verify20_binned.py`）显示，规则 5 的中间档已对齐
（亮度 ±0.05、色度 ≤0.1），但**暗部被抬升且色相相反**（C1 暖暗部 R/G 1.84 vs 我们冷 0.91），
高光被压暗——线性密度窗口表达不了胶片交叠（crossover）。

解法是 C1/NLP 同构的"打样响应"层：**按渲染亮度索引的每通道加性 LUT**，从 11 帧 C1 参照
一次性标定（`verify26_luma_lut.py`，配准 ≥0.60 的 4 帧参与拟合，常量烧入
`PRESCRIBED_PRINT_OFFSETS`）。加性修正不放大噪声、不压缩纹理；只作用于"没有可信片基"的帧
（`tone_mapping_mode = "prescribed_print_lut"` 标记，推导时与规则 5 均衡同门）。

- 回归：双跑 sweep 42/53 逐字节一致，11 个改变帧全部是 RAF（深欠曝 7 帧含窗口均衡，浅欠曝 4 帧
  仅 LUT 生效）；LR 拼接与全部正常素材不变。
- 效果：目视上深欠曝帧出现正确色相（蓝天/绿草/暖调黄昏），逐帧中位绝对差下降
  （1947 R 0.149→0.102、G 0.071→0.040、B 0.165→0.078）。
- **未竟**：逐帧残余 ±0.1 的色相差异（1943 偏暖、1944/1945 偏绿粉、1952 偏淡）来自每帧
  曝光/跨度的随机性，固定标定覆盖不到；下一步是"有界逐帧色度归一化"（C1 的自动白平衡同类
  调整，需产品决策），以及用更多参照提高标定质量（现仅 4 帧配准达标）。

### 12.6 三层重构：档案 + 有界逐帧归一化（2026-09-27）

加性 LUT 的两个结构性缺陷在验收中被确认：它把 C1 参照的**逐帧白平衡决策**（帧均值散布
R/G 0.875–1.087）连同胶片响应一起学进了常数——用常数拟合别人的逐帧决策，±0.1 残差原理上
封不死；且加性模型修暗部色相时必然耦合抬亮度（最暗档 +0.133R/+0.075G），产生"发灰的黑"。
重构为三层，各管各的误差源：

- **第 1 层 固定档案**（`PRESCRIBED_PRINT_LOG_RG/LOG_BG`，12 档亮度索引）：只学胶片
  crossover 的**形状**。标定（`verify27_joint_calib.py`）用双向中位数分解
  `log(参照色度) − log(我们的色度) = 档案(档) + 白平衡(帧)`，每帧白平衡作 nuisance 投影掉；
  档案按拟合档中位归零，常数归入逐帧项。配准升级为 8 朝向（发现 1944/45/51/52 存在镜像翻转）
  ×5 尺度，达标帧 4→5（1946 新纳入）；最暗两档是噪底，从第 3 档起拟合、向下恒定外推。
  留一验证显示形状跨帧可迁移（LOO 残差仅温和高于拟合内）。**亮度形状被数据否决**：
  分档亮度差逐帧反号（1942 与 1950 相反），是逐帧曝光决策不是胶片常数——色调归窗口与产品决策。
- **第 2 层 窗口推导**：规则 4/5 原样保留（帧均值对齐已完成，10/11 ≤0.103）。
- **第 3 层 有界逐帧归一化**（`apply_prescribed_chroma_normalizer`，渲染后一遍）：中间调内
  灰边缘估计器（边缘对大面积均匀色场稳健、中间调窗防天空支配蓝票——对比 C1 逐帧决策的
  bake-off 胜出）估每帧残余色偏，拉向中性，**钳位 ±8% log**、按亮度渐隐（[0.20,0.60] 全强度，
  余弦衰减到 [0.05,0.90] 的 1/4——中间调估计不得给真蓝天再补蓝）。1949 黄昏保护探针通过：
  保持中性，不追 C1 的风格化。

落地：核心内逐像素色度增益（亮度保持式，中性像素亮度严格不变、饱和像素二阶）+
包装函数后处理一遍归一化；`NEXFILM_PRINT_LUT_DISABLE=1` 同时关闭两层供 A/B。
验证：276 单测全过（新增 5 条契约：档案亮度保持、渐隐窗、估计器拉回+钳位、标记门控）；
双跑 sweep（`NEXFILM_RENDER_SWEEP=1` vs `NEXFILM_PRINT_LUT_DISABLE=1`）**42/53 逐字节一致，
11 个改变帧全部 RAF**，与加性 LUT 时代足迹完全一致；Rust 落地帧均值 R/G 散布
0.942–1.141（出货 0.796–1.128），1943 从 1.128/0.871 → 1.050/0.915，1952 从 0.865/1.082 →
1.001/1.043。最终拼图 `_review-final-three-layer.png`（出货 | Rust 三层 | C1，按配准朝向）。

**未竟**（交付决策用）：整体仍比 C1 偏淡——色调/对比度维度，C1 的逐帧自动曝光所致，
分档数据显示无跨帧共享的色调曲线可标定（1942/1950 高光反号），属产品决策（预设曲线或有界
逐帧对比度）；1945 仍是最差帧（1.141，跨度级残差超出 ±8% 钳位）；1942 型亮天空保留约
+0.08 B/G（渐隐只压了一半）；C1 的逐帧暖/冷风格化（如 1946 的 0.875）按设计不追。
