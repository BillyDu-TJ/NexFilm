## 零、问题总览

两类素材在自动反相（Auto Invert）后产生很离谱的偏色，而在 Capture One / NLP 里能得到可接受的结果：

| 族 | 素材 | 现象 | 备注 |
| --- | --- | --- | --- |
| A | `test_picture\富士raf\Capture One Catalog1942..1952.raf`（11 张，6×7 彩色负片机内翻拍） | 整幅偏蓝；改动后变成整幅偏红 | 每张都有对应的 Capture One 正片 `*.tif` 可作参照 |
| B | `test_picture\lr合并\*Pano.tif`（13 张，Lightroom 拼接 + 烘焙） | 中调偏青，云与暗部不能同时中性 | 11 张有参照正片（见第六节） |

两族的共同点：**窗口的通道响应是从画面内容估出来的**，而这些画面要么被上游工具改过通道、
要么被主导色（天空/海雾）占据，于是估出来的响应不是胶片/采集的响应。

## 一、问题 A：欠曝 RAF（根因链已核实）

### 1.1 文件事实

- 翻拍欠曝约 4–5 档：片基（画面内最亮 1%）只到满量程的 R 1.4–3.8% / G 0.5–2.1% / B 0.17–0.88%。
- 因此片基密度（`ProPhoto` 估计域）为 R 1.42–2.01 / G 1.68–2.34 / B 2.05–2.78 D。
- 应用确实使用相机的归一化 as-shot 白平衡（`WhiteBalancePolicy::NormalizedAsShot`），所以
  "没用机内白平衡"不是原因（已核实，见 `src/commands.rs` 的 RAW 解码路径）。

### 1.2 根因链

1. `FILM_BASE_MAX_DENSITY = 1.60`（绝对密度）与 `FILM_BASE_MAX_CHANNEL_SPREAD = 0.75`（通道差）
   两道判据都隐含"曝光正常"的假设，这批文件全部触发 → `estimate_film_base_f32` 返回
   `usable = false`，且（改动前）把 `density` 直接置 0，连实测值都不留。
2. 片基为 0 → 该帧落到"三通道共用一个跨度 + 每通道 ±0.20 D 原点偏移"的兜底窗口。
3. 色罩的通道差是 **0.3–0.5 D**（如 1942：R−G = −0.31、B−G = +0.48），装不进 ±0.20 →
   片基在成品里落到 **显示值 (0.30, 0.40, 0.79)**——片基发蓝，整幅发蓝。
   这就是"改动前整幅 R/G 0.32–0.63、B/G 1.39–2.12"的来源。

### 1.3 本轮改动（已提交 `3018fa4`，**效果不达标**）

- `FilmBaseEstimate` 增加 `candidate` 字段：无论判据是否接受，保留实测片基；
  `PipelineProcessingReport.film_base_candidate` 持久化该值。
- 渲染窗口：**只要这帧确实测到过片基（含被拒绝的），就保留它自己的逐通道同像素端点**，
  不再退到"共享跨度 + ±0.20"兜底。
- `DENSITY_WINDOW_RULE_VERSION` 3 → 4，旧帧下次自动反相时重新推导一次。
- 新增证据判定 `prescribed_response_evidence`（无可信片基 / 某通道基低于满量程 1% /
  三通道跨度比 > 2），**只进技术报告，不改变渲染**。

## 二、问题 B：LR 拼接（机理已量化，缺一条能验证的规则）

- 内容窗口的逐通道跨度比 = 1 : 1.97 : 2.99（蓝需要约 3 倍拉伸），窗口给出的固定比值只有
  R/G 0.508、B/G 1.518；而画面里"应当中性"的材料需要的比值随明度漂移
  （砂石 B/G 1.56 → 柱身 1.93，约 24%）。用这些比值反推成品 R/G，与实测渲染相差 ≤0.02。
- 现行（逐通道同像素端点）窗口在材料上已接近最优：中调分档残差 6.1%，**自由逐通道仿射的上限
  是 1.2%**；差距是一个很小的逐通道密度偏移（约 **R +0.015 D、B −0.014 D**）。
- 已实测否掉的形状：**三通道共享黑点**（8.7% vs 现行 6.1%，模型上限 1.2%）。
- 文档 `docs/unified-density-pipeline.md` §10.5 已经指出"共享原点 + 逐通道跨度"是另一套形状，
  需要重新对全部素材作观感验证——本轮结论与此一致。

## 四、度量方法的坑（下次务必避开）

1. **不要用"整幅平均通道比 ≈ 1.000"当中性判据**：它把随影调变化的偏色平均掉，我就是因此把明显
   的品红误报成"偏淡"。正确基准是**参照正片自身的帧均值**（`verify18.py`），或按影调分档。
2. **对照 harness 里不要用几何翻转去贴参考**：同一份几何也参与内容取样，会连带改变窗口
   （曾造成一组假象数字；已在 `3e858ca` 修正，改为在测量端做朝向搜索）。
3. **配准函数必须返回"偏移量所对应那张图"**：曾返回未旋转的图，导致回归斜率出现负值。
4. **以 Capture One 成品为绝对基准的"中性面残余"不稳定**（同一批数据给出 0.18–1.7，取决于配准、
   朝向、裁切与 C1 自身的白平衡选择）。要坐实绝对量化线，需要**含灰卡/已知中性物的样张**。
5. 检查"改变是否影响其它素材"时，最强证据是 `NEXFILM_RENDER_SWEEP=1` 的**全 fixture 逐字节渲染对比**
   （53 个可解码文件：11 张 RAF 帧变化，其余 42 个逐字节相同）。

## 六、下一步选项（按性价比）

1. **采集端根治（最有效，零代码）**：重拍这批负片时把片基推到满量程 60–80%（约加 4 档），
   机内白平衡设为固定值。这样既通过绝对密度判据，也把蓝通道从噪声底里救出来。
2. **给触发帧加"有界逐帧自动平衡"**：只对命中证据的帧生效，通道修正设明确上限（如 ±0.4 D），
   正常素材保持逐字节不变。原理上属于"从画面估计"，但数据显示常数处方做不到；这是唯一能让这批
   文件"肉眼无偏色"的机制。需要用户在产品取舍上点头。
3. **拼接族定规则**：用第六节新增的 11 张参照正片，判断那 ~0.015 D 的逐通道偏移是常数
   还是随通道截断程度变化（可复用 `verify19.py` 的拟合形态）。参照目录：
   `E:\Pictures\2026年\9.9 pro160ns\去色罩\原片\_DSC75xx-Pano.jpg`（11 张，7250×7261，已确认是
   中性正片）。注意：我们自己的 13 张 pano 渲染已在 harness 样本表里（需先跑一次生成图片）。
4. **回退并结案**：若接受"这类欠曝文件属于采集失败"，回退渲染改动、保留记录与判定，把这批素材
   归入"需要重拍"。
5. **绝对量化线**：只有拿到含灰卡的样张，才能给出可信的绝对中性残余标准（见第四节第 4 条）。
